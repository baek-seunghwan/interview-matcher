# PAIR — 카테부 실시간 모의면접 파트너 매칭

작성일: 2026-09-29 · 상태: MVP 구현

## 1. 누가, 언제 겪는 문제인가?

카테부의 AI 팀원을 비롯해 모의면접 파트너가 필요한 팀원들이 겪는 문제다. 주로 모의면접을 진행하는 월·화·수에 발생한다. AI 인원이 혼자인 팀, 타운홀 일정이 다른 팀, 파트너의 지각·외출로 혼자 남은 팀원이 대표 사용자다.

## 2. 현재 방식과 불편

파트너가 없으면 직접 다른 팀을 찾아가거나 Alex에게 HELP를 요청해야 한다. 면접 준비 시간에 사람을 찾느라 시간을 쓰고, 운영자에게 요청이 집중된다.

**목표: 같은 장소에 있는 사람들끼리 버튼 한 번으로 지금 연습할 파트너를 찾는다.**

## 3. 실제로 써볼 사람

파트너가 없는 AI 팀원, 대체 파트너가 필요한 팀원, 풀스택·클라우드 부서의 모의면접 참여자가 대상이다. 실제 참여 의사 확인이나 사용자 인터뷰는 아직 수행하지 않았다. 첫 파일럿은 같은 장소에 있는 팀원 6~10명에게 링크를 공유하여 진행한다.

## 4. 사용 흐름

1. 사이트에 접속한다.
2. **닉네임**을 입력한다. 예: Leon.
3. **팀**을 입력한다. 예: 14.
4. **부서 드롭다운**에서 AI / 풀스택 / 클라우드 중 하나를 선택한다.
5. **매칭 시작**을 누른다.
6. 같은 부서의 대기자가 있으면 즉시 연결한다. 없으면 다음 참여자를 기다린다.
7. 매칭된 상대의 닉네임과 팀을 확인하고 현장에서 바로 만나 면접을 시작한다.

**날짜·시간 선택, 장소 입력, 연락처 입력, 예약 과정은 없다.** 요일과 시간에 관계없이 즉시 사용할 수 있다. 같은 부서끼리 매칭하며, 팀이 같아도 매칭 가능하다.

## 5. 기능과 매칭 정책

| 기능/상황 | 동작 |
| --- | --- |
| 실시간 매칭 | 같은 부서에서 오래 기다린 순으로 1:1 연결 |
| 화면 갱신 | 2초마다 서버 상태를 확인; 새 신청자는 응답 즉시 결과 확인 |
| 홀수 인원 | 마지막 한 명은 다음 신청자를 기다림 |
| 동시 신청 | DB 트랜잭션으로 처리하여 같은 사람의 중복 배정 방지 |
| 중복 클릭 | 같은 브라우저의 활성 신청은 하나만 유지 |
| 대기 취소 | 대기열에서 제거 |
| 매칭 취소 | 본인은 취소, 상대는 다시 대기 |
| 다른 파트너 찾기 | 양쪽을 대기열로 돌리고 직전 상대를 제외하여 재매칭 |
| 면접 완료 | 양쪽을 완료 처리하고 다음 매칭 가능 |
| 대기 중 창 종료/연결 끊김 | 90초 이상 접속 확인이 없으면 대기 만료 |
| 매칭 이후 창 종료 | 매칭은 유지; 직접 취소/완료하거나 매칭 후 1시간에 만료 |
| 오류 | 입력을 유지하고 다시 연결 가능 |

‘실시간’은 서버에서 요청 즉시 매칭하며, 기존 대기자의 화면은 최대 약 2초 및 네트워크 지연 후 갱신되는 방식이다. WebSocket 방식은 아니다.

## 6. 화면

- 닉네임·팀 입력, 부서 드롭다운, 매칭 시작 버튼.
- 신청 전 / 대기 / 매칭된 상대 / 완료·취소·만료 상태.
- AI·풀스택·클라우드별 실제 대기 인원.
- 공유 링크 복사.
- PC·모바일 반응형 화면.

## 7. 데이터와 운영 한계

- 서버 Cloudflare D1에 매칭 상태를 저장한다. 브라우저에만 저장하는 모의 매칭이 아니다.
- 계정 없이 임의 HttpOnly 세션 쿠키로 브라우저를 구분한다. 서버에는 쿠키 비밀값 대신 SHA-256 해시를 저장한다.
- 닉네임·팀·부서·신청/접속/매칭 시각·상태·파트너 참조를 저장한다. 연락처와 장소는 수집하지 않는다.
- 닉네임·팀은 매칭 당사자에게만 제공한다. 전체 사용자 명단은 공개하지 않는다.
- 마지막 접속 확인으로부터 24시간 지난 기록은 다음 변경 요청 시 삭제한다. 예약 삭제 작업이 없으므로 사이트 사용이 중단되면 삭제가 지연될 수 있다.
- 쿠키를 삭제하거나 다른 브라우저·기기를 쓰면 별도 사용자로 취급한다. 실제 동일인이나 카테부 소속 여부를 인증하지 않는다.
- 최근 파트너 한 명만 재매칭에서 제외한다. 영구 차단 기능은 없다.
- 화상회의·채팅·메시지 알림은 포함하지 않는다. 같은 장소에서 직접 만난다는 전제다.

## 8. 효과 측정

기준 기간은 도입 전 1주와 파일럿 첫 1주다. 다음 목표는 검증 전 가설이다.

| 지표 | 측정 방법 | 초기 목표 |
| --- | --- | --- |
| 매칭 성공률 | 신청 중 파트너를 찾은 비율 | 80% 이상 |
| 직접 탐색/HELP 요청 | Alex에게 접수된 요청 수기 집계 | 기존 대비 50% 감소 |
| 실제 진행률 | 매칭 후 실제 면접을 진행했는지 설문 | 80% 이상 |
| 재사용 의향 | 다음에도 쓸 것인지 설문 | 5점 중 평균 4점 이상 |

현재 앱에는 별도 분석 이벤트 이력이나 대시보드가 없다. 신청 기록은 재신청 때 덮어쓰고 24시간 이후 삭제하므로 기간 전체 KPI를 현재 DB만으로 계산할 수 없다. 첫 파일럿은 익명 설문과 운영 집계로 확인하고, 필요가 검증되면 개인정보 없는 이벤트 집계를 추가한다.

## 9. 출시·파일럿 기준

- 서로 다른 두 브라우저에서 같은 부서로 매칭 시작 시 양쪽에 상대 닉네임·팀이 표시된다.
- 서로 다른 부서는 연결하지 않는다.
- 여러 사람이 동시에 눌러도 중복 배정되지 않는다.
- 취소·재매칭·완료 결과가 양쪽에 반영된다.
- 팀원들이 함께 접속해야 매칭이 가능하다. 대기자 없이 가짜 상대를 만들지 않는다.

후속 우선순위: 실사용 피드백 → 팀원 인증·다기기 복구·요청 제한 → 익명 성과 측정. 날짜 예약이나 장소 입력은 요구 범위에 포함하지 않는다.
